#### Коммит 6: `fix(gui): suppress console window flash when querying git version`
- **Проблема:**
  - При запуске `PhoneGyro.exe` на долю секунды («наносекунду») мелькало чёрное окно консоли `cmd.exe`/`conhost`.
  - Причина: `PhoneGyro.exe` скомпилирован как GUI-приложение Windows (`IMAGE_SUBSYSTEM_WINDOWS_GUI`) без прикрепленной консоли. При старте функция `version.Get()` в локальных dev-сборках вызывает `gitInDir()` (`exec.Command("git", ...)`). Запуск консольного процесса (`IMAGE_SUBSYSTEM_WINDOWS_CUI`) из GUI-процесса без флага `CREATE_NO_WINDOW` заставляет Windows создать новое окно консоли для `git.exe`, которое закрывалось сразу по завершении git.
- **Что сделано:**
  - Создан хелпер `prepareCmd(cmd)`:
    - Для Windows (`cmd_windows.go`): выставлены атрибуты процесса `cmd.SysProcAttr = &syscall.SysProcAttr{ HideWindow: true, CreationFlags: 0x08000000 }` (`CREATE_NO_WINDOW`).
    - Для остальных ОС (`cmd_other.go`): пустая заглушка-no-op.
  - В `version.go` и `version_test.go` добавлен вызов `prepareCmd(cmd)` перед выполнением команды.
  - Окно консоли теперь гарантированно не появляется при запуске и в тестах.

#### Коммит 14: `fix(gui): decouple frontend DOM events from backend lifecycle and add resilient Wails polling`
- **Что исправлено:**
  - **Устранение блокировки UI при раннем выходе (Wails Injection Race Condition):**
    - В начале `<script>` стояла проверка `if (!rt || !app) return;`. В WebView2 при парсинге HTML-документа объекты `window.runtime` и `window.go` инжектируются Wails асинхронно с задержкой в несколько миллисекунд. Синхронное выполнение скрипта наталкивалось на пустой `window.go` и немедленно завершало работу. ## Архитектурные стандарты системы (Non-Negotiable)

### 1. Стандарт единиц измерения и масштабирования (Unit & Scaling Standard)
- **Запрет на статический хардкод пикселей:** Никаких случайных разрозненных значений `width: 48px; height: 30px` в правилах компонентов.
- **Иерархия единиц:**
  1. **Глобальный макет и сетка:** токены отступов (`--space-1...10`), типографика (`display-xl`, `body`, `mono` на базе Onest/Alegreya/JetBrains).
  2. **Изолированные компоненты (Controls, TitleBar, Islands, Badges):** параметрические размеры через масштабный токен `--[component]-scale` и формулы `calc(base * var(--scale))`, либо относительные единицы `em` от локального `font-size`.
  3. **Бритвенно-чёткие границы (Hairlines):** строго `1px solid var(--line)` (или `line-subtle`). Не переводить в относительные единицы, чтобы избежать размытия и мерцания при субпиксельном рендеринге в Chromium/WebView2 на экранах 100% DPI.
  4. **Запрет `vh`/`vw` внутри тела окна:** ломает зум интерфейса Wails (`PhoneGyro.zoom`); высота задаётся через `100%`, flex/grid и `@container pgwin`.

### 1a. Единицы: rem + em (закреплено 2026-10-01)
- **rem** — все размеры интерфейса (1rem = 16px): отступы, размеры, шрифты, радиусы, тени. Весь UI масштабируется
  одним `font-size` корня.
- **em** — пропорции внутри компонента от его шрифта (кольцо «o» в словесном знаке и т. п.).
- **px только**: волосяные линии `1px`/`0.5px`; условия `@container`/`@media` (меряют окно); геометрия внутри SVG
  (viewBox, dasharray); HTML-атрибуты width/height у картинок (подсказка до загрузки CSS).
- `css/pg.css` из дизайна (там px) переводится автоматически: `tools/design-css/units.py` в генераторе.
  `css/app.css` пишется сразу в rem; проверить: `python tools/design-css/units.py gui/frontend/src/css/app.css`.
- В JS размеры тоже в rem (например, ход пузырька циферблата — `device.js`).

### 2. Вопрос шрифтов (пункт 3)
- В `docs/internal/Design/fonts/` лежат 8 готовых WOFF2 файлов общим весом ~210 КБ:
  - `Onest` (Regular, Medium, SemiBold, Bold) — для основного интерфейса;
  - `Alegreya Sans` (Bold, ExtraBold) — для акцентных заголовков и брендинга;
  - `JetBrains Mono` (Regular, SemiBold) — для чисел, телеметрии, таймеров и версий.
- Эти файлы в `Design/fonts/` **уже являются оптимизированными сабсетами** (содержат только Latin + Cyrillic без лишних редких символов).
- Текущие микровырезки шрифтов (base64 по ~920 байт) в `index.html` создавались исключительно для пустого окна-заглушки (чтобы отрисовать только «PhoneGyr» и цифры релиза без внешних запросов).
- При переходе к полноценным экранам и русскоязычному интерфейсу шрифты из `Design/fonts/` будут подключаться локально как полноценная типографика системы (без внешних CDN).

#### 2. Архитектурное предложение по компоновке вкладки

##### Почему единая страница «всё в одном» отвергнута (борьба с захламлением)
В LEGACY и в ранних прототипах объединение 3D-просмотра, таблиц DSU, 10 карточек со спарклайнами, CSV-рекордера, осциллографа и мини-игр на одном экране приводило к тому, что интерфейс разваливался («оно всё там попадало», «кринж»). Во время игры пользователь видел скачущие цифры пакетов DSU, прогресс-бары и технические дампы, что убивало концентрацию и FPS.

##### Решение: 3 логических подвкладки через верхний сегментный переключатель `.pg-seg`
В шапке экрана «Статистика & 3D» прямо под плавающим островком навигации размещается аккуратный сегментный контрол:
```
[ 🖥 3D и телеметрия ]   [ 🎮 Мини-игры ]   [ 📈 Стенд отклика ]
```

##### 1. Подвкладка «3D и телеметрия» (`telemetry`):
- Строго следует эталону `docs/internal/Design/screens/ScreenTelemetry.html` (двухколоночный сплит `.pg-tel`).
- **Слева (`.pg-tel__side`):**
  - Карточка контролов: выбор 3D-модели (Геймпад / Кубик), переключатель экономии ресурсов (Eco mode), кнопка «Центрировать» (с шорткатом `Пробел`).
  - Карточка CSV-рекордера: кнопка «Начать запись» с мигающей точкой, таймер `00:00 / 01:00`, прогресс-бар, строки/килобайты, бейдж лимита 1 мин.
  - Карточка статуса аппаратного протокола USB (L1–L5): динамически видна только при подключенном USB-контроллере.
  - Сетка метрик `.pg-stats`: 10 карточек с SVG-спарклайнами (Частота, Задержка, Джиттер, Потери, Сырой гироскоп, Сырой акселерометр, DSU выход, Пайплайн, Клиенты DSU с бейджем процесса, DSU гироскоп).
- **Справа (`.pg-tel__views`):**
  - Селектор режимов камеры `.pg-seg.pg-tel__mode`: `[ Статический | 4 камеры | Динамический ]`.
  - При `Статический` или `Динамический`: просторный видовой экран `GyroScene` на всю высоту с подсказкой орбиты («ЛКМ вращение • Колёсико зум») и кнопкой сброса ракурса (`R`).
  - При `4 камеры`: 4 квадрантных вьюпорта (`FRONT`, `TOP`, `RIGHT`, `3/4 ISO`) с кольцами и перекрестиями.
  - Оверлеи отключения («ОФФЛАЙН: подключите смартфон») и паузы эко-режима.

##### 2. Подвкладка «Мини-игры» (`games`) — строго минималистичный HUD:
- **Никакого информационного шума вокруг игрового поля!**
- **Компактная HUD-панель сверху:**
  - Переключатель игры: `[ 🏹 Прицел Zelda ]` | `[ ⛩️ Платформа святилища ]`.
  - Счётчики: `Очки: 14`, `Рекорд: 32`.
  - Таймер: капсула `00:18.4` (для тира) или текущие углы наклона `P: +2.4° R: -1.2°` (для платформы).
  - Быстрые кнопки: `[ ▶ Старт / Сброс ]`, `[ Пробел Центрировать ]`, `[ ⛶ Во весь экран ]`.
- **Игровая сцена по центру:**
  - Просторный высококонтрастный холст без посторонних рамок.
  - Для «Прицела»: мишени с золотым яблочком, анимированный шеихский прицел лука.
  - Для «Платформы»: святилищный каменный постамент, светящиеся руны, лунка, катающийся шарик.
- **Скрытые инженерные настройки:**
  - Внизу под сценой размещён свёрнутый блок `<details class="app-game-disclosure">`:
    `▶ ⚙ Дополнительные параметры теста (скрыты во время игры)`
  - Внутри: переключатель потока (DSU с фильтром / Сырой датчик), инверсия X/Y, задержка пайплайна. По умолчанию свёрнут и не отвлекает.

##### 3. Подвкладка «Стенд отклика» (`bench`):
- Фокусируется на исследовании формы волны и динамической задержки.
- **Шапка:** выбор источника (DSU / Сырой поток), бейдж стабильности (`🟢 Стабильно`), уровень шума (`1.2%`), пинг.
- **Осциллограф:** холст на 140 кадров истории, переключатель осей `[ Pitch (X) | Yaw (Y) | Roll (Z) | Все 3 оси ]`.
  - На графике одновременно рисуются сырая кривая (микродрожание датчика) и сглаженная кривая DSU.
- **Нижний блок настройки фильтрации:**
  - Ползунки Deadband (Порог дрожи) и Sensitivity (Чувствительность): изменение значений мгновенно отражается на плавности живой волны на осциллографе.

#### 3. Производительность и ресурсы

1. **Ленивая загрузка (Zero initial footprint):**
   - Three.js (`vendor/three.min.js`, ~600 КБ) и `vendor/gyroscene.js` подгружаются динамически через `js/ui/scene.js` только в момент первого переключения на вкладку «Статистика & 3D».
   - До этого момента память процесса чиста, WebGL-контекст не создаётся.
2. **Нулевой rAF в покое (Strict Rule 0):**
   - При уходе с вкладки «Статистика & 3D» или сворачивании окна вызывается `scene.dispose()`, rAF-циклы останавливаются, подписки на `ahrs:quat` и `tuning:frame` снимаются через `off()`.
   - Графики сети и ресурсов обновляются только по приходу событий бэкенда (≤15 Гц), без постоянных холостых rAF.
