# PhoneGyro — мастер-промпт для агента (новый UI)

Ты работаешь над PhoneGyro: Go + Wails v2 приложение для Windows. Телефон (страница в браузере) или USB-контроллер
(Arduino Nano + MPU-6050) → источник движения Cemuhook DSU (UDP 26760) для эмуляторов (Cemu и др.).
Сейчас идёт **переписывание интерфейса с нуля** в ветке `frontend-rework`. Владелец — тестировщик: он смотрит
результат глазами и пишет замечания. Ты пишешь код, проверяешь его сам и отчитываешься честно.

Отвечай владельцу **по-русски**, коротко и по делу.

---

## 0. Самое важное правило

**Мы делаем новые функции, но никогда не теряем старые.**

- Старый интерфейс лежит в `LEGACY/frontend` — это трафарет того, *что приложение умеет*. Не чинить, не подключать,
  но **перед тем как переписывать или удалять что-то, найди это в LEGACY и перенеси всё поведение**.
- Удалить функцию (пункт настроек, кнопку, диалог, горячую клавишу, звук) можно только по прямой просьбе владельца.
  «Выглядит лишним» — не причина. Если сомневаешься — спроси, не удаляй.
- Если функция есть в Go (`gui/internal/**`), у пользователя должен остаться способ ею управлять.
- Перед сдачей задачи: пройдись по тому, что затронул, и сверь со старым поведением в LEGACY.

## 1. Где что лежит

- Дизайн-система (источник правды по виду): `docs/internal/Design/` — `README.md`, `MIGRATION.md`,
  `components/<Name>/README.md` + `preview.html` (эталон разметки), `components/bundle.css`, `bundle.js`.
  Актуальная версия — в артефакте владельца; новые файлы он кладёт туда же.
- Журнал переписывания, архитектура, чеклисты: `docs/internal/frontend_rework_log/README.md`. Читай перед работой.
- Новый фронт: `gui/frontend/src/`
  - `index.html` — разметка оболочки и экранов, без логики;
  - `css/pg.css` — **СГЕНЕРИРОВАН** `tools/design-css/build.py` из дизайна. Руками не править никогда;
  - `css/app.css` — только то, чего нет в дизайн-системе;
  - `js/core/` — `bridge.js` (вызовы Go: `call('Метод', …)`, события `on('event', fn)`), `state.js` (одно состояние
    Go, `onState(fn)`), `i18n.js` (`t('ключ')`), `dom.js` (`setText/show/…` пишут только изменения);
  - `js/shell/` — заголовок окна, шапка, подвал, роутер экранов; `js/ui/` — общие виджеты (modal, toast, tooltip,
    select, zoom, accent); `js/screens/` — экраны; `js/vendor/` — **сгенерированные** куски `bundle.js`.
- Строки: только `pkg/i18n/locales/ru.json` и `en.json` (новые — в раздел `ui`). В JS и HTML текст не хардкодить.
- Go-API для UI: публичные методы `func (a *App) …` в `gui/internal/app/*.go` (привязки в `gui/frontend/wailsjs`).

## 2. Как копировать дизайн-систему

- Вид и разметку **копируешь** из `components/<Name>/preview.html`, классы `pg-*` — не выдумываешь свои аналоги.
- Нужен кусок из `bundle.js` → добавь его вырезку в `tools/design-css/build.py` (как `accent.js`), а не копируй руками.
- Обновился дизайн → положи новые `bundle.css/js` в `docs/internal/Design/components/`, запусти
  `python tools/design-css/build.py` (Python с Pillow), проверь экраны.
- Цвета — только токены (`var(--accent)`, `--ink`, `--surface`…). Никаких hex в компонентах. Акцент — только
  `--accent*`, зелёный не хардкодить.
- Окна, которых нет в дизайне (например уведомления), собираются из существующих классов (`pg-modal`, `pg-notice`,
  `pg-card`…) по образцу соседних экранов.

## 3. Единицы: rem + em, НЕ px

- Все размеры интерфейса — `rem` (1rem = 16px): отступы, размеры, шрифты, радиусы, тени. В JS тоже.
- `em` — пропорции внутри компонента от его шрифта.
- `px` только: волосяные линии `1px`/`0.5px`, условия `@container`/`@media`, геометрия внутри SVG,
  атрибуты `width/height` у `<img>`.
- Брейкпоинты окна — `@container pgwin (...)`, не `@media`. `vh/vw` внутри приложения не использовать (ломают зум).

## 4. Производительность

- Состояние приходит ~15 раз в секунду: в DOM пиши только изменения (`setText`, `setHTML` с кэшем, ключ-сравнение).
- Никаких циклов `requestAnimationFrame`, которые крутятся постоянно; анимация — засыпает, когда нечего делать.
- Анимации — только `transform` и `opacity`.
- Тяжёлое (модули окон, картинки) — грузить лениво, когда понадобилось.

## 5. Git и правила владельца

- Коммиты только в текущую ветку (`frontend-rework`). `main` не трогать. Пуш — только по команде.
- Стиль: `type(scope): описание` по-английски, тело — зачем. **Никогда** не добавлять `Co-Authored-By: Claude`
  и «Generated with Claude Code».
- Один коммит — одна логическая правка. Не смешивай свою работу с чужими незакоммиченными изменениями:
  увидел их в `git status` — спроси владельца.
- Ничего не удалять без подтверждения (файлы, функции, настройки).
- Не трогать `LEGACY/` (кроме чтения), `docs/internal/Design/` (кроме обновления бандла по просьбе).
- Перед `wails build` проверь, что `PhoneGyro.exe` не запущен (`tasklist | findstr PhoneGyro`); если запущен —
  не собирай, скажи владельцу.
- Тесты (`go test`) не запускай без просьбы: часть требует доступа брандмауэра. `go build ./...` и `go vet` — можно.
- Отклонённые идеи (не предлагать): 3D-уровень на Three.js (оставлен CSS-циферблат), 6-позиционная калибровка
  акселерометра, температурная модель, калибровка масштаба гироскопа.
