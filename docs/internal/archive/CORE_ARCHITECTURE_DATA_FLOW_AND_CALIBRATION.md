## 1. Введение и глобальная архитектура

Архитектура GyroBridge представляет собой строго детерминированный пайплайн реального времени с ультранизкой задержкой (< 4 мс end-to-end от датчика iPhone до эмулятора ПК).

```
+-------------------------------------------------------------------------+
|                              IPHONE SAFARI                              |
|  devicemotion (60 Hz) / deviceorientation                               |
|  - Обнуление угловых скоростей при засыпании/пробуждении                |
|  - Rate-limiting & Fallback Heartbeat                                   |
|  - Перевод осей в радианы/сек                                           |
+------------------------------------+------------------------------------+
                                     | WebSocket Binary / JSON (TLS)
                                     v
+-------------------------------------------------------------------------+
|                         GO BACKEND (pkg/server)                         |
|  - Сериализация / Джиттер-буфер                                         |
|  - Вычитание нуля гироскопа: w_unbiased = w_raw - gyroBias              |
|  - Матрица калибровки: w_cal = M * w_unbiased                           |
|  - Конвертация знаков под Cemuhook DSU (dsuRy = -ry * scale)            |
|  - Фильтр акселерометра: Table Lock [0, -1, 0] + EMA (alpha 0.20/0.05)   |
+-------------------+---------------------------------+-------------------+
                    |                                 |
                    v                                 v
+-------------------------------+ +---------------------------------------+
|    CEMUHOOK DSU (pkg/dsu)     | |         GUI / ВИЗУАЛИЗАЦИЯ            |
|  - UDP Server (Port 26760)    | |  - Madgwick AHRS (Beta = 0.0)         |
|  - Magic DSUC / DSUS          | |  - LiveDebug WebSocket (60 Hz + us)   |
|  - 5-секундный таймаут клиента| |  - Wails Events (state:change)        |
|  - Cemu / Yuzu / Ryujinx /    | |  - Three.js 3D Viewport (RAF Lerp)    |
|    Dolphin / RPCS3 / PadTest  | |  - Stillness Recal Hint (cooldowns)   |
+-------------------------------+ +---------------------------------------+
```

## 2. Поток 1: От сенсоров iOS до Cemuhook DSU

### 2.1 Сбор данных в браузере (web/index.html)
В браузере iOS Safari источником данных выступает событие `devicemotion`:
- `e.rotationRate`: угловые скорости в градусах/сек вокруг осей устройства (`alpha`, `beta`, `gamma`).
- `e.accelerationIncludingGravity`: вектор ускорения с учетом гравитации в м/с^2 (`x`, `y`, `z`).

**Преобразование координат в клиенте:**
- Угловые скорости приводятся к радианам в секунду: $\omega_{rad} = \omega_{deg} \times \frac{\pi}{180}$.
- Акселерометр нормализуется в единицы $g$: $a_g = \frac{a_{m/s^2}}{9.80665}$.
- Для портретного режима Safari:
  - `rotX = beta * (PI / 180)`
  - `rotY = gamma * (PI / 180)`
  - `rotZ = alpha * (PI / 180)`
  - `accX = x / 9.80665`
  - `accY = y / 9.80665`
  - `accZ = z / 9.80665`

### 2.2 Транспортный уровень (WebSocket Framing)
Клиент отправляет кадры на защищенный порт WebSocket (`wss://<IP>:8443/ws`):
- **Основной транспорт:** Бинарный буфер `ArrayBuffer` фиксированной длины 50 байт (Little-Endian) с аппаратным таймстемпом:
  - `uint64 timestamp_us` (микросекунды, `performance.now() * 1000` на клиенте или `micros()` на MCU)
  - `float32 rotX, rotY, rotZ` (градусы/сек)
  - `float32 qx, qy, qz, qw` (кватернион устройства)
  - `float32 accX, accY, accZ` (g)
  - `uint16 buttons` (флаги кнопок/паузы)
- **Обратная совместимость:** Поддерживается 46-байтный бинарный кадр с `uint32 timestamp_ms`.
- **Резервный транспорт:** JSON-кадры при отладке.

### 2.3 Серверный приемник (pkg/server)
В файле `pkg/server/server.go`:
- WebSocket читает входящие датаграммы без блокировки.
- Кадр распаковывается в структуру `MotionFrame`:
  ```go
  type MotionFrame struct {
      Timestamp   uint32
      TimestampUs uint64
      RotX, RotY, RotZ float32
      AccX, AccY, AccZ float32
      Qx, Qy, Qz, Qw   float32
      Buttons          uint16
  }
  ```
- Кадр немедленно передается в колбэк `OnFrame` приложения `App`.
- Ведется учет статистики: частота входящих кадров (`inHz`), пинг, число активных клиентов.

### 2.4 Калибровочный конвейер (Transform Pipeline)
В методе `onFrame` файла [gui/app.go](file:///M:/00_Coding/00_Projects/iphone-gyro-controller/gui/app.go):

1. **Вычитание статического смещения нуля (Stationary Zero-Bias):**
   ```go
   a.biasMu.RLock()
   bx, by, bz := a.gyroBias[0], a.gyroBias[1], a.gyroBias[2]
   a.biasMu.RUnlock()

   rawX := float64(frame.RotX) - bx
   rawY := float64(frame.RotY) - by
   rawZ := float64(frame.RotZ) - bz
   ```

2. **Применение калибровочной матрицы $M$:**
   Калибровочная матрица $M \in \mathbb{R}^{3 \times 3}$ связывает сырые оси смартфона с каноническими осями геймпада:
   $$\begin{pmatrix} rx \\ ry \\ rz \end{pmatrix} = M \begin{pmatrix} rawX \\ rawY \\ rawZ \end{pmatrix}$$
   
   Реализация:
   ```go
   rx = m[0][0]*rawX + m[0][1]*rawY + m[0][2]*rawZ
   ry = m[1][0]*rawX + m[1][1]*rawY + m[1][2]*rawZ
   rz = m[2][0]*rawX + m[2][1]*rawY + m[2][2]*rawZ
   ```

3. **Конвертация в градусы/сек и специфика DSU:**
   ```go
   scale := float32(180.0 / math.Pi)

   // Для внутреннего AHRS (правая система)
   ahrsRx = float32(rx) * scale
   ahrsRy = float32(ry) * scale
   ahrsRz = float32(rz) * scale

   // Для протокола Cemuhook DSU:
   // По конвенции Cemuhook поворот носа вправо (по часовой стрелке) должен быть отрицательным.
   dsuRx = float32(rx) * scale
   dsuRy = -float32(ry) * scale
   dsuRz = float32(rz) * scale
   ```

### 2.5 Фильтрация акселерометра и Table Lock

**Физическая проблема:**  
Эмулятор PadTest использует алгоритм Madgwick AHRS, который нормализует вектор градиентной ошибки:
$$2 \beta \frac{\mathbf{s}}{\|\mathbf{s}\|} \approx 11.5^\circ / \text{с}$$
Даже электрический шум сенсора амплитудой всего $0.003g$ приводит к постоянному 60 Гц дребезгу (limit-cycle oscillation).

**Инженерное решение — двухрежимный фильтр:**
1. **Режим Table Lock (Удержание стола):**
   Если телефон неподвижен (`gyroSpeed < 0.25` град/с) и вектор ускорения близок к положению лежа на столе (`|ax| < 0.06`, `|ay + 1.0| < 0.08`, `|az| < 0.06`):
   - Акселерометр жестко фиксируется в значении:
     $$\mathbf{a}_{final} = (0.0, -1.0, 0.0)$$
   - Градиент ошибки в Madgwick AHRS обращается в точный нуль ($0.000000^\circ/\text{с}$). Дрожание полностью отсутствует.
2. **Режим движения (Moving / Hands):**
   Применяется экспоненциальное скользящее среднее (EMA):
   $$\mathbf{a}_{filtered}^{(t)} = \mathbf{a}_{filtered}^{(t-1)} + \alpha \cdot (\mathbf{a}_{raw}^{(t)} - \mathbf{a}_{filtered}^{(t-1)})$$
   - $\alpha = 0.20$ при активном движении (быстрое следование за гравитацией).
   - $\alpha = 0.05$ при микро-движениях (устранение высокочастотного шума).
3. **Мгновенный сброс фильтра (`accFilterReset`):**
   Флаг `atomic.Bool` сбрасывает `accFiltered` к текущему сырому значению в первый же кадр после подключения, разблокировки или смены видимости. Это исключает затягивание старых значений на 60 кадров.

### 2.6 Протокол Cemuhook DSU (pkg/dsu)
В файле `pkg/dsu/dsu.go`:
- UDP-сервер слушает входящие запросы на порту `26760` (или кастомном из настроек).
- **Магические заголовки:**
  - `DSUC` (0x43555344) — клиентский пакет (Client to Server).
  - `DSUS` (0x53555344) — серверный ответ (Server to Client).
- **Типы сообщений:**
  - `0x100000`: Информация о версии протокола (версия `1001`).
  - `0x100001`: Запрос информации о контроллерах (Слот 0: DualShock 4 / Motion Plus).
  - `0x100002`: Подписка на поток данных движения и отправка отчетов.
- **Учет подписчиков:**
  Клиенты регистрируются с меткой времени `lastSeen`. Если от эмулятора нет пакетов в течение 5 секунд, клиент удаляется из списка рассылки.
- **Пакет данных (DSU Motion Data Report):**
  Отправляется со скоростью 60-120 Гц:
  - `Timestamp` в микросекундах (вычисляется методом `calcNextTimestamp`: транслирует точный аппаратный шаг времени $\Delta t$ датчика, исключая джиттер Wi-Fi и предотвращая накопление ложного ухода угла Yaw в фильтре Mahony эмулятора Cemu).
  - Акселерометр: $A_x, A_y, A_z$ в $g$.
  - Гироскоп: $\Omega_x, \Omega_y, \Omega_z$ в градусах/сек.

## 3. Поток 2: Поток визуализации и телеметрии

### 3.1 Фильтр ориентации Madgwick AHRS
Для отображения 3D-модели в реальном времени используется собственный фильтр `MadgwickAHRS` ([gui/ahrs.go](file:///M:/00_Coding/00_Projects/iphone-gyro-controller/gui/ahrs.go)), идентичный реализации PadTest:
- `Beta = 0.0`: фильтр выполняет чистое гироскопическое интегрирование ориентации без гравитационной коррекции при нейтральном положении.
- Кватернион состояния:
  $$\mathbf{q} = (q_0, q_1, q_2, q_3) = (w, x, y, z)$$
- Углы Эйлера вычисляются по стандартным формулам авиационной навигации (Tait-Bryan ZYX):
  $$\text{Pitch} = \arcsin(2(q_0 q_2 - q_3 q_1)) \times \frac{180}{\pi}$$
  $$\text{Roll} = \text{atan2}(2(q_0 q_1 + q_2 q_3), 1 - 2(q_1^2 + q_2^2)) \times \frac{180}{\pi}$$
  $$\text{Yaw} = \text{atan2}(2(q_0 q_3 + q_1 q_2), 1 - 2(q_2^2 + q_3^2)) \times \frac{180}{\pi}$$

### 3.2 Канал LiveDebug (Standalone 60 Hz HUD)
Для глубокой диагностики без нагрузки на основной интерфейс:

- Передаются:

  - Сырые и откалиброванные векторы гироскопа и акселерометра.
  - Метрики задержки: `pipeMs` (время прохождения пайплайна в Go в микросекундах), `recvTs`, `sendTs`.
  - Частота кадров входа и выхода (`inHz`, `outHz`).

### 3.3 3D Viewport и RAF Lerp Loop в GUI
В файле [gui/frontend/src/index.html](file:///M:/00_Coding/00_Projects/iphone-gyro-controller/gui/frontend/src/index.html):
1. **Рендерер Three.js:**
   - 3D-модель геймпада ориентируется по кватерниону AHRS или углам Эйлера.
2. **Экспоненциальное сглаживание (Lerp RAF Loop):**
   Для предотвращения ступенчатости при 120/144 Гц мониторах в цикле `requestAnimationFrame`:
   ```javascript
   const factor = 0.22;

   ```
3. **Пузырьковый уровень (Inclinometer):**
   Отображает наклон устройства с визуальным радиусом смещения:
   $$r = \min(40.0, \sqrt{\text{Pitch}^2 + \text{Roll}^2})$$

### 3.4 Детектор неподвижности и Stillness Recalibration Hint
Всплывающий баннер с предложением перекалибровки появляется исключительно при одновременном выполнении условий:
1. Контроллер онлайн и не на паузе.
2. Ни одно модальное окно не открыто (Calibration, Setup, Help, Settings).
3. Прошло более 45 секунд с момента предыдущего закрытия баннера (`_recalHintDismissedTs`).
4. **Прошло более 3.5 секунд с момента последнего переподключения или разблокировки экрана (`_reconnectCooldownTs`).**
5. Устройство неподвижно: дельта углов между кадрами $|\Delta P| < 0.12^\circ$ и $|\Delta R| < 0.12^\circ$.
6. Неподвижность сохраняется непрерывно дольше 2.2 секунд.
7. При этой неподвижности горизонт смещен: $|P| > 10.0^\circ$ или $|R| > 10.0^\circ$.

При малейшем движении устройства таймер покоя немедленно сбрасывается (`_stillnessStart = 0`), а баннер плавно исчезает.

## 4. Математика калибровки (Calibration Mathematics)

Калибровка GyroBridge решает задачу нахождения матрицы ориентации $M \in O(3)$, совмещающей оси смартфона (держащегося в любом положении: вертикально, горизонтально, вверх ногами) с канонической системой координат Cemuhook DSU.

```
 Канонические оси DSU:
 +X = Pitch (наклон вперед: RotX < 0)
 +Y = Yaw   (поворот по часовой стрелке: RotY < 0)
 +Z = Roll  (крен вправо: RotZ > 0)
```

### 4.1 Шаг 0: Калибровка покоя и вычисление смещения (Bias)
Телефон неподвижно лежит на поверхности. За 1.5–2 секунды накапливается буфер из $N \ge 20$ отсчетов.

1. **Среднее смещение гироскопа (Zero-Bias):**
   $$\mathbf{b} = \frac{1}{N} \sum_{i=1}^{N} \boldsymbol{\omega}_i$$
2. **Проверка стабильности покоя (Anti-Shake Guard):**
   Вычисляется среднеквадратичное отклонение:
   $$\sigma = \sqrt{\frac{1}{N} \sum_{i=1}^{N} \|\boldsymbol{\omega}_i - \mathbf{b}\|^2}$$
   - Если $\sigma > 2.5^\circ/\text{с}$ или $\max \|\boldsymbol{\omega}_i\| > 6.0^\circ/\text{с}$, шаг бракуется с кодом `error_moved_during_rest`.
3. **Захват гравитационного вектора:**
   $$\mathbf{g}_{unit} = \frac{\sum \mathbf{a}_i}{\|\sum \mathbf{a}_i\|}$$

### 4.2 Шаги 1 и 2: Динамические жесты (Pitch и Roll)
Пользователь выполняет 2 интуитивных жеста:
- **Шаг 1 (Pitch / "Кивни"):** Наклон телефона вперед/назад.
- **Шаг 2 (Roll / "Самолётик"):** Крен телефона влево/вправо.

Анализ каждого жеста:
1. **Вычитание смещения:** $\boldsymbol{\omega}' = \boldsymbol{\omega} - \mathbf{b}$.
2. **Кинетическая энергия вращения по осям:**
   $$E_j = \sum_{t} (\omega'_{j, t})^2, \quad j \in \{0, 1, 2\} \ (X, Y, Z)$$
3. **Выбор доминирующей физической оси:**
   $$k = \arg\max_{j} E_j$$
   Метрика уверенности:
   $$\text{Confidence} = \frac{E_{\max} - E_{\text{second}}}{E_{\max}} \ge 0.15$$
4. **Определение направления первой полуволны жеста:**
   Анализируется первый переход через порог $\text{threshold} = \max(8.0^\circ/\text{с}, 0.25 \cdot |\omega_{\max}|)$.
   - $s_{detected} \in \{+1.0, -1.0\}$.
5. **Построение канонического вектора строки:**
   По формуле:
   $$\mathbf{row}_k = s_{target} \cdot s_{detected} \cdot \mathbf{e}_k$$
   - Для Pitch: целевой знак наклона вперед $s_{target} = -1.0$.
   - Для Roll: целевой знак крена вправо $s_{target} = +1.0$.

### 4.3 Проверка ортогональности и детекция смены хвата
Векторы строк нормализуются и привязываются к ближайшим кардинальным осям:
$$\mathbf{v}_{snapped} = \text{snap}(\mathbf{v})$$
- Если индекс доминирующей оси Pitch совпадает с индексом Roll ($\text{idx}_P == \text{idx}_R$), калибровка прерывается с ошибкой `error_grip_changed` (пользователь изменил хват или совершил некорректное движение).

### 4.4 Вычисление Yaw и паритет Cemuhook (det = -1.0)
Третья ось (Yaw) вычисляется через векторное произведение:
$$\mathbf{yaw}_{temp} = \mathbf{pitch} \times \mathbf{roll}$$

Формируется матрица:
$$M = \begin{pmatrix} \mathbf{pitch} \\ \mathbf{yaw}_{temp} \\ \mathbf{roll} \end{pmatrix}$$

**Критическое правило паритета Cemuhook DSU:**
Протокол Cemuhook DSU использует **левую** систему координат, поэтому определитель матрицы должен строго равняться:
$$\det(M) = -1.0$$
Если вычисленный $\det(M) > 0$:
$$\mathbf{yaw} = -\mathbf{yaw}_{temp}$$
$$M = \begin{pmatrix} \mathbf{pitch} \\ -\mathbf{yaw}_{temp} \\ \mathbf{roll} \end{pmatrix}$$

Проверка валидности определителя:
$$|\det(M) - (-1.0)| \le 0.05$$
Если условие нарушено, калибровка бракуется с кодом `error_invalid_determinant`.

### 4.5 Матричные преобразования в реальном времени
Сформированная матрица $M$ сохраняется в активный слот профиля (всего 6 слотов в `%APPDATA%/gyrobridge/profiles.json`).

В реальном времени каждый поступающий вектор угловой скорости смартфона умножается на $M$:
$$\begin{pmatrix} \omega_{pitch} \\ \omega_{yaw} \\ \omega_{roll} \end{pmatrix} = \begin{pmatrix} M_{00} & M_{01} & M_{02} \\ M_{10} & M_{11} & M_{12} \\ M_{20} & M_{21} & M_{22} \end{pmatrix} \begin{pmatrix} \omega_{x} - b_x \\ \omega_{y} - b_y \\ \omega_{z} - b_z \end{pmatrix}$$

Благодаря ортонормированности матрицы cross-axis утечки равны нулю, а движения изолированы по трем осям.

## 5. Архив проблем и их инженерные решения

### 5.1 Слет гироскопа и наклон горизонта при блокировке/разблокировке iOS

- **Симптомы:** После выключения экрана iPhone и последующей разблокировки горизонт в 3D Viewport оказывался наклоненным на 15–30°, появлялся баннер калибровки, а в играх прицел медленно уползал.
- **Корневые причины:**
  1. *Клиент (web/index.html):* При блокировке событие `devicemotion` прекращалось, а переменные `dsuPitch`, `dsuYaw`, `dsuRoll` сохраняли последние ненулевые значения. При пробуждении браузер до первого кадра сенсора отсылал старые угловые скорости.
  2. *Бэкенд (gui/app.go):* Внутренний фильтр `a.ahrs` работал с $\beta = 0.0$ (чистое интегрирование). Во время сна он «запоминал» старый угол наклона и не возвращался к горизонту.
  3. *Фильтр акселерометра:* `accFiltered` за счет медленного коэффициента $\alpha = 0.05$ сглаживал переход из кармана/рук на стол в течение нескольких секунд.
- **Инженерное решение:**
  1. В `web/index.html` при `visibilitychange` (и в `hidden`, и в `visible`) переменные `dsuPitch = 0`, `dsuYaw = 0`, `dsuRoll = 0` немедленно обнуляются.
  2. В `web/index.html` в методе `onOrientation` и в heartbeat-интервале: если с момента последнего кадра прошло > 200 мс, угловые скорости обнуляются перед отправкой.
  3. В `gui/app.go` введен атомарный триггер `accFilterReset`. При событиях `OnClientConnect`, `OnClientDisconnect` и `OnClientVisibility(visible=true)` вызывается сброс фильтра и метод `a.ResetAHRS()`.
  4. В `gui/frontend/src/index.html` добавлен кулдаун 3.5 секунды после переподключения/пробуждения (`_reconnectCooldownTs`), блокирующий ложное появление баннера Stillness Recalibration Hint.

### 5.2 60 Гц микро-дребезг на столе (PadTest Limit Cycle)

- **Симптомы:** В эмуляторах при неподвижно лежащем на столе телефоне график угловой скорости и прицел непрерывно дрожали с частотой 60 Гц.
- **Корневая причина:** Нормализация вектора градиента в Madgwick AHRS усиливает белый шум акселерометра $0.003g$ до ступеньки $11.5^\circ/\text{с}$.
- **Инженерное решение:** Введен детерминированный Table Lock: при `gyroSpeed < 0.25` и векторе ускорения около $[0, -1, 0]$ акселерометр фиксируется в $[0.0, -1.0, 0.0]$, что полностью обнуляет градиентную ошибку.

### 5.3 Инверсия осей и соглашение знаков DSU

- **Симптомы:** В Cemu и Yuzu поворот геймпада влево приводил к повороту камеры вправо.
- **Корневая причина:** Протокол Cemuhook DSU ожидает левостороннюю ориентацию и отрицательный знак при повороте по часовой стрелке вокруг вертикальной оси Y.
- **Инженерное решение:** Вектор матрицы DSU инвертирует ось Yaw: `dsuRy = -ry * scale`, а калибровочный валидатор гарантирует $\det(M) = -1.0$.

### 5.4 Разрыв соединения WebSocket при усыплении экрана iOS

- **Симптомы:** Safari закрывает WebSocket при блокировке экрана. После включения экран отображал разорванное соединение.
- **Инженерное решение:** В `web/index.html` при событии `visibilitychange` (`state === 'visible'`) проверяется состояние сокета. Если сокет закрыт, вызывается немедленный повторный коннект `connectWSS()`. В бэкенде Go установлен таймер задержки отключения 2.5 секунды, предотвращающий мерцание UI при кратковременных сетевых просадках.

### 5.5 Доверие сертификатам WebPKI на iOS

- **Симптомы:** iOS Safari категорически блокирует WSS на локальные IP-адреса с самоподписанными сертификатами.
- **Инженерное решение:** Создан полнофункциональный микро-центр сертификации `pkg/ca`. Сервер генерирует корневой сертификат CA и раздает его в виде профиля `.mobileconfig` по обычному HTTP (порт 8080). После установки профиля на iPhone и включения доверия в «Настройки -> Основные -> Об этом устройстве -> Доверие сертификатам» Safari работает с WSS нативно и без предупреждений безопасности.

### 5.6 Ложные срабатывания антивирусов на Go/Wails бинарники

- **Симптомы:** Эвристические анализаторы VirusTotal выдавали флаги (Heur.Bzc).
- **Инженерное решение:**
  - Переход на нативный загрузчик WebView2 (`-tags native_webview2loader`).
  - Очистка таблицы символов и отладочных DWARF-секций при сборке: `-ldflags="-s -w -buildid="`.
  - Отказ от UPX-упаковщиков, вызывающих эвристические алерты.

## 6. Чек-лист целостности алгоритма

При любых будущих модификациях кода обязательно проверять:

1. [ ] **Детерминант калибровки:** $\det(M) == -1.0$ (Cemuhook Left-Handed Parity).
2. [ ] **Знак осей DSU:** `dsuRy` строго инвертирован относительно правой системы координат AHRS.
3. [ ] **Table Lock:** При покое на столе Acc фиксируется в $[0.0, -1.0, 0.0]$.
4. [ ] **Сброс скоростей на клиенте:** `dsuPitch = 0, dsuYaw = 0, dsuRoll = 0` при `visibilitychange`.
5. [ ] **Сброс фильтров на сервере:** `a.accFilterReset.Store(true)` и `a.ResetAHRS()` при подключении и смене видимости.
6. [ ] **Кулдаун баннера:** Защитный интервал 3.5 секунды после переподключения.
7. [ ] **Все юнит-тесты:** `go test ./...` и `go test ./gui/...` завершаются с кодом `0`.
