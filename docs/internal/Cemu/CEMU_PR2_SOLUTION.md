## 3. PR 2: спецификация

Всё живёт в `MahonySensorFusion` (`Mahony.h`); `updateGyroBias` получает dt и акселерометр. Вызов остаётся на
месте — в `updateIMU` после обрезки dt до 0.2 с. Интерфейсы (`getGyroBias`, `WiiUMotionHandler`, `MotionSample`),
зона 0.015 в кватернионе и провайдеры (кроме коммита DSU из §4) не меняются.

**Новое состояние:** экспоненциальные среднее и дисперсия гироскопа и акселерометра по трём осям; флаг «первый
образец принят»; таймер покоя; флаг «дальний режим»; флаг «покой уже был»; предыдущий образец гироскопа и время
его побитового повтора. Старые сумма и счётчик остаются — это фолбэк.

**На каждый образец:**
1. Первый образец: средние = образец, дисперсии = 0 (иначе первые секунды «остывают», как в первой версии V3).
2. k = min(dt / 0.25 с, 1). Для каждой оси обоих датчиков: d = x − среднее; среднее += k·d;
   дисперсия = (1 − k)·(дисперсия + k·d²).
3. **Покой**, если на всех осях: дисперсия гироскопа < 0.01², дисперсия акселерометра < 0.02², \|среднее
   гироскопа\| < 0.35 рад/с.
4. **Нет покоя**, если dt ≥ 0.1 с (разрыв) или гироскоп побитово повторяет прошлый *ненулевой* образец дольше
   1 с (зависший источник). Точные нули не трогаются — ими в покое кормят PhoneGyro и другие калиброванные
   источники.
5. **Покоя ещё не было** → старый алгоритм работает побитово как сейчас, и его результат — текущее смещение.
6. Не покой → таймер = 0, дальний режим снят, выход.
7. Таймер += dt. Дальний режим = покой уже был и хотя бы на одной оси \|среднее − смещение\| ≥ 0.01 рад/с.
   **При входе в дальний режим таймер начинается заново** (исправление №1).
8. Нужно 1 с покоя, а в дальнем режиме 3 с. Не набралось → выход.
9. Первый покой или дальний режим → смещение = среднее. Иначе смещение тянется к среднему с k = dt / 3 с.
   Отметить «покой был»: с этого момента старый алгоритм больше не вызывается.

| Константа | Значение | Почему |
|---|---|---|
| усреднение | 0.25 с | несколько периодов тремора 8–12 Гц; быстрая реакция |
| СКО гироскопа в покое | 0.01 рад/с (0.57 °/с) | ваш MPU-6050 на столе 0.09–0.19 °/с (запас 3–6×), в руке 0.3–2 °/с |
| СКО акселерометра | 0.02 g | стол ~0.004 g. **Нужен:** без него спокойная рука с поворотом 2 °/с даёт 98 % вместо 0 % |
| предел среднего | 0.35 рад/с | равен старому фильтру: V3 не сужает поддерживаемый диапазон |
| первый покой / обычное обновление | 1 с | проверено: при 2 с теряется покой 1.5 с (60 %), при 3 с — покои по 3 с (99.8 %) |
| полоса «рядом» | 0.01 рад/с (0.57 °/с) | ниже зоны gyroChange 0.012 (PR 1) |
| покой для скачка | 3 с (только в дальнем режиме) | плавное движение без дрожи редко длится 3 с |
| слежение | 3 с | температура; гладкость |
| разрыв | 0.1 с | ≥ 6 пропущенных образцов при 60 Гц |
| повтор | 1 с | ловит зависание раньше 3-секундного скачка; у настоящего датчика в покое шум меняет младшие разряды, секунда побитовых повторов почти невозможна |

**Объём:** ~60 строк в `Mahony.h`. Если ревьюер попросит меньше, первым убирать повтор (−8 строк; риск
исправления №3 вернётся), вторым — разрыв (−2 строки). Сдвиг таймера (№1) и фолбэк не убирать.

**Лог (по желанию, +3 строки):** `cemuLog_log(LogType::InputAPI, …)` с новым смещением, но только при первом
покое и принятом скачке, не при слежении. Для разбора отчётов вроде #1825.

## 4. Отдельный коммит: сброс DSU при смене устройства

- В начале `DSUControllerProvider::integrate_motion` сравнить MAC пакета (`GetMacAddress()`, это `std::array`)
  с последним MAC этого слота. Если отличается — пересоздать обработчик слота, обнулить метку времени слота,
  запомнить MAC.
- Сравнивать **до** проверки меток: иначе пакеты нового устройства с меньшими метками до 10 с отбрасываются.
- Серверы, шлющие нулевой MAC, сброса не получат — это прежнее поведение.
- Первый пакет после сброса приходит с огромным dt. Mahony обрежет его до 0.2 с, а правило разрыва не даст счесть
  его покоем. Всё как с самым первым пакетом сегодня.
- Новое поле называть по стилю (`m_motionMac`), даже если соседние в snake_case: `CODING_STYLE.md` требует новый
  стиль всегда.
- Эффект: «другое устройство на слоте (0 → 2 °/с)» — 0.8 % вместо 2.9 %. Новое устройство начинает с чистого
  листа, как при запуске Cemu, и не получает чужое смещение.

## 6. Известные ограничения PR 2 (писать в PR честно)

Любой детектор покоя по дисперсии гироскопа можно обмануть **плавным движением без дрожи** — на опоре или от
источника со сглаживанием. Это следствие §6 постановки, а не реализации:
- поворот на колене дольше 3 с: 62.6 % (сейчас 92.9 %);
- контроллер плавно поворачивают на столе до первого покоя (10 °/с, 2.5 с): 59.9 % (сейчас 99.4 %);
- многократный медленный разгон 0 → 3 °/с за 20 с без дрожи: 78 %, 2.5 °/с (сейчас 92 %, 1.34 °/с).

Во всех трёх случаях всё равно лучше, чем сейчас. Лечится следующим настоящим покоем.

Как сейчас остаются: никогда не лежавший контроллер, неверные единицы у сервера, вибрирующая поверхность,
смещение ≥ 0.35 рад/с. Если #1825 окажется последним случаем — предел можно поднять до 0.5 (расширение, а не
регрессия). Цена: за первый покой может быть принято плавное вращение до 29 °/с.

## 7. PR 3 (по желанию): «ни разу не положил»

**Идея.** Сейчас дрейф создаёт не среднее, а несимметричный фильтр по скорости: из петли «медленно туда, быстро
обратно» он выбрасывает только обратную половину. Среднее *всех* образцов с весом dt равно смещению плюс чистый
поворот / время. Игрок смотрит в экран, поворот ограничен, значит ошибка затухает. Отличие смещения от движения —
в накопленном угле: 5 °/с — это 300° в минуту без предела.

**Спецификация** (работает только пока покоя не было, поверх фолбэка):
- окна по 30 с: сумма ω·dt по осям, сумма \|ω\|²·dt, время;
- разрыв ≥ 0.1 с начинает окно заново;
- окно годно, если СКО \|ω\| ≤ 0.5 рад/с (отсекает махи и быстрый конинг);
- два годных окна подряд с разницей средних < 0.5 °/с по каждой оси → оба в копилку. Дальше в копилку идёт
  каждое годное окно, согласное с предыдущим;
- смещение = среднее копилки, вместо значения старого алгоритма.

~25 строк, 3 константы.

**Результаты:**
- «ни разу не положен» чинится примерно за минуту (10–13 % времени против ~100 %) на 60/100/1000 Гц;
- ни в одном из 14 стресс-тестов не хуже старого алгоритма: переворот, разворот на 360° (один и два подряд),
  поворот на 90° с новым курсом, дрейф курса, конинг 0.25/0.33/1 Гц, насыщение ±250 °/с (окна отсеиваются,
  остаётся старый алгоритм).

**Слабые места:**
- непрерывный медленный конинг (15°, 0.2 Гц, 2 мин): 0.53 °/с, 31 %. Более быстрый (1/3 и 1 Гц) отсекается
  фильтром активности;
- непрерывное вращение 2 °/с три минуты: 0.63 °/с, 61 %.

Сейчас в обоих случаях ~4 °/с и 99.6 %.

**Когда подавать:** после принятия PR 2 или если ревьюер сам спросит про «никогда не кладут».

## 8. PR 1: оставить, но описать честно

**Issue (EN):**
> **Gyro aim slowly drifts after asymmetric motion, even when the motion source sends exact zeros at rest**
>
> `MahonySensorFusion::updateGyroBias` estimates the gyro bias as the mean of all samples in which every axis is
> below 0.35 rad/s, over the whole session and without forgetting. Aiming is usually asymmetric (slow pan one way, fast flick back):
> the slow part is averaged in, the fast return is filtered out, so the estimate moves towards the slow direction
> and stays there. At rest the game then receives `-bias` in VPAD gyroChange; above 0.015 rad/s the orientation
> drifts too. The same `MotionSample` feeds the emulated Wii Remote MotionPlus.
>
> Repro: DSU source that is calibrated (a packet capture shows exactly 0 °/s at rest), BotW bow aiming for a few
> minutes → the aim keeps drifting horizontally while the pad lies still. Restarting Cemu clears it; disconnecting
> the source does not. Replaying the captured packets through `updateGyroBias` gives +0.83 °/s on Y after one
> slow pan. Possibly related: #1825.

**PR 2 (EN):**
> **input: Only update the gyro bias while the controller is at rest**
>
> Fixes #… The bias estimate now changes only while the controller is at rest: the gyro spread (exponentially
> weighted std over ~0.25 s) is below 0.01 rad/s and the accelerometer spread below 0.02 g on every axis, with
> the mean below 0.35 rad/s (the same limit as the old filter). The first estimate is taken after 1 s of rest;
> later, values within 0.01 rad/s are followed smoothly, while a larger change needs 3 s of rest at the new value,
> so slow tremor-free rotation is not mistaken for bias. A sample after a gap (≥ 0.1 s) or a stalled source
> repeating the same non-zero sample does not count as rest. All timing uses deltaTime (60–1000 Hz behave the
> same).
>
> Until the controller has been at rest once, the previous estimator runs unchanged, so a controller that is never
> put down (e.g. a Switch Pro with a large offset held from the start) behaves exactly as before.
>
> Second commit: the DSU motion state of a slot is reset when the device MAC changes, so a new device does not
> inherit the previous bias and its packets are not dropped by the timestamp check.
>
> Tested with: … Interfaces and threading are unchanged (state lives in `MahonySensorFusion`, updated only by the
> provider thread).

**К PR 1 добавить (EN):**
> Note: the filter never took effect before, so this introduces a per-axis dead zone of 0.012 rad/s (~0.69 °/s) for
> VPAD gyroChange and for the emulated MotionPlus angular rate. For comparison, Dolphin's default gyro dead zone is
> 2 °/s.

## 11. PhoneGyro и побочные находки

**PhoneGyro:**
- Подсказка в UI при подключении: «положите телефон на 1–2 секунды». После первого покоя старый алгоритм
  выключается до перезапуска Cemu или смены устройства на слоте.
- Обходной путь со служебными пакетами оставить, пока исправленный Cemu не разойдётся. После PR 2 он влияет только
  на фазу до первого покоя и безвреден для нового алгоритма. Минус прежний: каждый служебный пакет подменяет
  опубликованный `MotionSample` до следующего настоящего, и игра может прочитать всплеск. Нужен выключатель.
- Проверить на своих записях СКО акселерометра **в руке**. Ваша зона нечувствительности (USB 0.5 °/с) в
  спокойной руке часто даёт точные нули. Если и акселерометр там < 0.02 g, первый покой случится прямо в руке, и
  «ни разу не положил» для PhoneGyro почти исчезает.
- Не делать «пачку нулей при подключении» ради обмана детектора: это подделка покоя, завязанная на константы
  Cemu.
- Никогда не повторять последний ненулевой образец со свежими метками при зависании датчика — лучше не слать
  ничего. Cemu после PR 2 это отфильтрует, но другие эмуляторы — нет.

**Побочные находки (не для этих PR):**
- SDL Switch кладёт 3 выборки отчёта в события с **одним** временем. Cemu из-за проверки `dif <= 0`
  (`SDLControllerProvider.cpp:218`, `:240`) берёт только первую, самую старую: по Bluetooth ~66 Гц вместо 200 и
  лишние ~10 мс задержки. Лечится переходом на `sensor_timestamp` — отдельный PR с проверкой драйверов, где он может быть 0.
- HLE VPAD принимает и молча игнорирует настройки гироскопа от игры (zero drift, `SetGyroDirection`, DirRevise).
- После обновления SDL до версии с `ef6e76e` Switch-контроллеры станут калиброванными уже в SDL.
- В #1825 после PR 2 попросить у автора значения из лога (если лог добавите): так видно, не больше ли смещение
  клона 0.35 рад/с.
